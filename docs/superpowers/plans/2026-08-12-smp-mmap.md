# Dual-Core SMP + File-Backed mmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring up a second CPU core on a shared run queue (Redox-hybrid scheduler) and add file-backed mmap with demand paging.

**Architecture:** Per-CPU `CpuLocal` state (TSS/GDT/syscall-state/current-thread) in a kernel-static array `CPUS`, one shared `SCHEDULER` queue, APs parked on a wake condition (`RUNNABLE_COUNT`) instead of busy-polling. File-backed mmap adds `VmaKind::File { fd, offset }` and reads file blocks into frames on demand-fault.

**Tech Stack:** Rust `no_std` kernel, x86_64 (long mode), naked-asm interrupt handlers, SpinLock globals, QEMU + pexpect boot tests, ext2 filesystem.

**Baseline (already landed, not in this plan):** INV1 fix, `ls` fix, TAR fallback-only. See `docs/superpowers/PROGRESS.md`.

---

## Scope check

This plan covers two subsystems (SMP scheduler, file-backed mmap). They share the per-CPU current-thread work, so the mmap fault path depends on SMP's `CpuLocal`. Sequence:

- **Phase 1** (Tasks 1-5): pure single-CPU refactor — introduce `CpuLocal` as the single-CPU holder, migrate `CURRENT_THREAD`/`CPU_STATE` into `CPUS[0]`, keep everything else unchanged. Safe, testable at every step.
- **Phase 2** (Tasks 6-9): dual-core — MADT detection, trampoline, AP bring-up, per-core timer switch, wake model.
- **Phase 3** (Tasks 10-13): file-backed mmap.
- **Phase 4** (Task 14): syscall/VFS cleanup sweep.

Each task leaves the kernel booting and passing the existing boot tests.

**QEMU test harness:** all boot tests use `scripts/qemu.sh -display none` driven by pexpect (pattern in `scripts/crash_run.py`). A helper `scripts/boot_test.py` runs a command and asserts a substring; used throughout.

Replace the `todo!`s:

```rust
fn signal_runnable() {
    RUNNABLE_COUNT.fetch_add(1, core::sync::atomic::Ordering::Release);
}

fn ap_idle_loop() -> ! {
    let my_id = current_cpu_id() as usize;
    loop {
        let last = RUNNABLE_COUNT.load(core::sync::atomic::Ordering::Acquire);
        // drain the shared queue
        let next = {
            let mut q = SCHEDULER.lock();
            q.pop_front()
        };
        match next {
            Some(t) => { run_thread_on_core(my_id, t); }
            None => {
                // park until RUNNABLE_COUNT changes (wait-for-change, then re-poll)
                while RUNNABLE_COUNT.load(core::sync::atomic::Ordering::Acquire) == last {
                    unsafe { core::arch::asm!("hlt"); }
                }
            }
        }
    }
}

/// Runs `t` to completion of its timeslice on core `my_id` — returns the new rsp.
fn run_thread_on_core(my_id: usize, t: Thread) {
    // set CPUS[my_id].current = Some(t); cr3/fs_base/rsp0; then iretq into t.stack_ptr
    todo!("switch into t; on next timer tick it round-robins back into SCHEDULER")
}
```

> Note: `ap_idle_loop` is the AP-side mirror of the BSP's own run. In this design the AP pulls from the shared queue exactly like the BSP's timer handler pushes. The `hlt` park is the "condition on the shared-queue lock" from the spec (RUNNABLE_COUNT as the counter). IPI wake is out of scope.
